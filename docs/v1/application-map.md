## Runtime and dependency graph

`index.html` is the entry point. This is a client-side Spanish-language traffic/cellular-automaton simulator with an editable campus street graph, scenarios, charts, virtual time, and two rendering paths. Most `src/js/` files are **classic browser scripts**, not ES modules: there are no JS `import`/`export` edges in the application runtime. `index.html:2299-2370` determines script load order; scripts share top-level lexical bindings and `window` properties, register DOM listeners, and often execute initialization at evaluation time. Avoid assuming that moving a script or changing `const`/`let` globals is local.

```text
index.html (DOM, script order, CSS)
  ├─ local Bootstrap 5.0.2 CSS/JS, local Chart.js UMD
  ├─ CDN Pyodide 0.25.0 + JSZip 3.10.1 + PixiJS 7 (runtime globals)
  ├─ renderer/utils → renderer base classes → renderer/renderers
  ├─ core/bezierStreet → core/curvas, ClickActionManager, escenarios, tiempo, estacionamientos
  ├─ core/trafico (simulation state + built-in map + Canvas fallback + Pixi bridge)
  │    ├─ renderer/PixiApp → SceneManager → individual renderers
  │    └─ core/graficas (per-step metrics) + ui/infoBar (per-step status)
  └─ ui/ (constructor/editor/scenario/time/chart/analysis controls)
       └─ ui/analizadorMetricas → Pyodide → src/python/analizador.py
```

`apps/v1/package.json`: Vite 8 dev server, Vitest 4 tests, Puppeteer Core for browser checks; scripts `dev`, `test`, `test:smoke`, `test:baseline:record`, `lint`. No build-time application imports; dependencies loaded by HTML URLs. `servidor.py` is an alternative Python static server; `INICIAR_SERVIDOR.bat` starts it on Windows. `vitest.config.js` picks `tests/**/*.spec.{js,mjs}`. Root `assets/images/{vehicles,roads,objects,buildings}/` holds simulation sprites; `src/assets/logos/` holds favicon/branding. `src/bootstrap-5.0.2-dist/` and `src/libs/chart.js/` are vendored libraries. `dist/`, `.turbo/`, `node_modules/` are outputs/dependencies; `src/css/estilos.css.txt` is an extra text copy, not linked by HTML. `src/js/ui/loadingAnimation.js` exists but is **not loaded** by `index.html` (unlike `loadingSystem.js`). `src/js/renderer/EditorHandles.js` also exists but the **loaded** implementation is `src/js/renderer/renderers/EditorHandles.js` at `index.html:2311`; both declare `EditorHandles` and assign `window.EditorHandles`.

### Shared model and change propagation

- `core/trafico.js:68-242` owns automaton rule table `reglas` (vehicle values 1–6, empty 0, obstruction 7), `TIPOS` (`generador`, `conexion`, `devorador`), `TIPOS_CONEXION`, `calles`, `conexiones`, cell size, pause/scale/offset, and exports many `window.*` references. `crearCalle` (`:694-740`) creates per-lane cell arrays/geometry. `ConexionCA` (`:741-934`) transfers cars and describes lineal/incorporación/probabilística links; helpers at `:2169-2282` instantiate/register them. Built-in topology is constructed inside `iniciarSimulacion` (`:2342-4014`). `ui/constructor.js` owns `window.referenceImage` and its image decoding/JSON lifecycle; `trafico.js` and `SceneManager.js` draw it in world coordinates.
- A tick runs **generation → connection transfers → lane changes → street automaton update → virtual clock → metrics → redraw → info bar**, in `trafico.js:4128-4180`; keep that ordering when changing traffic rules. `animate` (`:4181-4200`) schedules it through `requestAnimationFrame`; pause/step/slider handlers follow.
- `core/curvas.js` modifies street vertices/curved-cell coordinates. `core/estacionamientos.js` connects building parking cells to streets. `core/escenarios.js` stores blockers/floods/potholes in street state. `core/tiempo.js` supplies clock and hourly traffic multiplier. `core/graficas.js` reads street cells on each step. `ui/constructor.js` serializes/restores streets, connections, buildings, clock and scenario state; after modifying their shape, inspect its save/load ranges.
- Renderer reads globals (`window.calles`, `window.edificios`, `window.conexiones`, `window.escala`, offsets) and writes selection globals. `PixiApp` constructs `SceneManager` and `CameraController`; `SceneManager` delegates to renderers. Canvas 2D fallback draws in `trafico.js`. Check both paths for geometry, selection, scenario or visibility changes. Mutating/replacing arrays can leave stale `window.*` references: inspect both owner and consumer.
- Map-first straight-street drawing is owned by `ui/drawStreet.js` (loaded after `ui/constructor.js`); it uses `crearCalle`, updates the street selectors, and dispatches `street-drawn`. `ui/streetInspector.js` owns the Draw button, exact street/Bezier controls, conversion from straight to Bezier, and quantized dimension commits. `ui/editStreetGeometry.js` owns selected Calle endpoint/control handles and direct movement/resize gestures in both renderers, loaded after the inspector. Pixi camera pan yields to the active draw tool on pointer down. Structural changes pause through `window.streetEditPause` in `trafico.js`; explicit Resume finishes focused edits and gestures.

- Map-first directed Lineal connection drafting is owned by `ui/createLink.js`, loaded after the street editing tools. The draft is separate from live `window.conexiones` until Save; Canvas and Pixi map picks use the shared street hit test, and committed mappings use the existing connection model and registration path.

## Narrow-reading workflow

Pick the feature route, read the listed function/range in the owning file and the adjacent consumer(s), then check the matching HTML IDs and both renderer paths if visual behavior is involved. When modifying state or serialization, trace the `window` exposure and load order first. For topology or tick changes, compare with the baseline fixture; for UI changes, use the smoke path. If these locations have moved, search for the named function within the identified file before searching the whole tree, and update this map after the change.
